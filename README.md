# じぶんノート

## 1. サービス概要

「この場面なら自分はこうする」という35の質問に答えて、自分の強みを7つの診断軸から見つける自己理解アプリです。

面接で自己アピールが必要な受験生・就活生が、自分の得意なこと・長所を言葉にできるようにします。

さらに家族や友人にも同じ質問に答えてもらい、「自分から見た自分」と「他者から見た自分」を比べることで、自分では気づいていない強みまで理解を深められるようにします。

---

## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験

自分を表現するのが苦手で、実際に就職するときに、自己理解があまりうまくできなかった。

### 2-2. なぜ気になったのか

面接で自己アピールするときに、自分の得意なこと・苦手なこと・長所・短所を理解して、相手にうまく伝えることができなかったから。

## 3. 課題の整理

### 3-1. 表に見えている困りごと

既存の診断は、自分を理解するための内容に深さがない。
質問に答えていって、最後に出てくる「あなたってこういう人」という総評に、「本当かな？」と思ってしまう。

### 3-2. 本当に解決したい課題

なぜ総評に納得できないのか？

- 質問の内容が浅い
- 質問の数が足りない
- 総評がうまくない

→ **本当に解決したい課題：自分で「確かに」と納得できる総評がないこと**

## 5. 既存サービス・競合調査

### 5-1. 似たサービス

1、16Personalities

16タイプに分類
無料のオンライン性格診断診断結果では16種類のタイプ（例: INTJ、ENFP など）に加え、Assertive（A） と Turbulent（T） の追加指標を用いた分類が提示される
各タイプについて、強みや課題、恋愛、人間関係、職業適性などの詳細な解説記事も提供している

2、PersonalityPick

自己理解や自己省察を目的としたサービス

回答の組み合わせを解析し、利用者ごとに文章を組み立てる仕組みを採用している

16アーキタイプは既存のMBTIや他社の分類をそのまま利用したものではなく、長年研究されてきた人格特性の考え方を参考にしつつ独自に設計したモデル

3、日本MBTI協会

一般的なインターネット上の「16タイプ診断」と区別し、MBTIの目的はタイプ分けや適性判定ではないらしい（公式回答）

回答者が認定ユーザーの支援を受けながら自身の認知スタイルや心理的な傾向を理解し、多様な価値観への理解を深めるための枠組みを重視

専門の知識を持った人と自分のことを理解していくタイプの診断内

## 7. このアプリで実現すること

### MVP で作る機能

- ユーザー登録・ログイン（Devise）
- 自己診断（35問・1問ずつ回答・途中保存と再開・回答の確認と見直し）
  - 質問は「この場面ならどうするか」を5択で答える形式
  - 1つの選択肢から2〜3の診断軸に点数が入る配点（質問・選択肢・配点は DB で管理）
- 7つの診断軸（分析力・課題解決力・行動力・協調性・学習力・継続力・発想力）のスコア
  - 平均的な答え方を50点とする0〜100点（軸ごとの点の入りやすさの差をならす）
- 結果画面
  - 総合タイプ（上位2軸の組み合わせ21タイプ＋オールラウンダー）
  - 強みTOP3（強みとして働く場面・もっと活かすヒント）
  - あなたのこんな良さ（スコアが低めの軸も、良さとして伝える）
  - 7軸のレーダーチャート
- マイページ（過去の診断結果の一覧・最初からやり直す）
- 結果の SNS シェア
- 利用規約・プライバシーポリシー

### 本リリースで作る機能

- 他者診断
  - 他者診断用の URL を発行し、家族や友人にログインなしで回答してもらう
  - 関係性（友人・家族など）と「この人を一言で表すなら？」の自由記述
- 自分と他者の診断結果の比較（7軸の差分）
- 自分では気づいていない強み（自分の評価が低く、他者の評価が高い軸）

### まだ分からない
- AI による「自分の取扱説明書」の文章化
- 面接で使える自己PR・具体例の文章の生成
- パスワード再設定（メール送信）

## 8. 懸念点と対策

### 懸念点①：質問の内容と回答の数

- **何が問題になりそうか**：質問が浅かったり少なかったりすると、既存サービスと同じように総評に納得できない
- **対策**
  - 7つの診断軸 × 5問の35問にした
  - 質問は、学校や仕事の経験がなくても答えられる日常の場面（旅行・遊び・家事など）にし、「この場面ならどう行動するか」を選ぶ形にした
  - 同じような選択肢が並ばないよう、1問ずつ文章を見直した
  - 1つの回答で複数の軸に点数が入るようにし、特定の軸だけが高く出ないよう、配点をシミュレーションで調整した

### 懸念点②：総評の深さ

- **何が問題になりそうか**：「あなたは〇〇タイプです」だけでは、「本当かな？」と思われてしまう
- **対策**
  - 総合タイプに加えて、強みTOP3ごとに「強みとして働く場面」と「もっと活かすヒント」を表示する
  - 点数が低い軸も「悪い」とは表現せず、「低めのときの良さ」として伝える
  - 本リリースで「他者から見た自分」を加え、自分だけの回答では出せない総評にする

## 10. 技術スタック

### 10-1. 使用技術

- フレームワーク：Ruby on Rails 8.1（Ruby 3.4）
- DB：PostgreSQL 16
- デプロイ先：Render
- 使用ライブラリ
  - Devise / devise-i18n / rails-i18n（ログイン・日本語化）
  - Tailwind CSS（tailwindcss-rails）
  - Hotwire（Turbo / Stimulus）
  - Chart.js（レーダーチャート）
  - RSpec / FactoryBot（テスト）
  - RuboCop / Brakeman（コードの書き方・セキュリティのチェック）
- 開発環境：Docker（compose.yml）
- CI：GitHub Actions（RuboCop・Brakeman・RSpec）

### 10-2. 技術選定の比較検討

| 候補 | 採用/不採用 | 理由 |
|---|---|---|
| Ruby on Rails 8.1 | 採用 | RUNTEQ で学んでいる。7.2 はセキュリティサポートが終了しているため、公開する MVP ではサポート中の 8.1 を選んだ |
| Next.js | 不採用 | 企画段階で試作したが、とりあえずなしで　画面を作り込む場合は本リリース後に検討する |
| PostgreSQL | 採用 | Render で使え、公開後も安心して使える |
| SQLite | 不採用 | 試作では使ったが、公開するサービスの本番 DB には向かない |
| Devise | 採用 | ログイン・登録・アカウント編集がそろっていて、日本語化（devise-i18n）もある |
| Sorcery / Rails 8 の認証ジェネレーター | 不採用 | 必要な機能を自分で作る部分が増えるため |
| Hotwire（Turbo / Stimulus） | 採用 | Rails 標準で、React なしで「1問ずつ表示」などの動きを作れる |
| React | 不採用 | 学習コストが大きく、MVP の期間では Rails の学習を優先する |
| Chart.js | 採用 | レーダーチャートが簡単に描ける。importmap で読み込める |
| Render | 採用 | Rails をそのまま公開でき、RUNTEQ の卒業制作でもよく使われている |
| Docker | 採用 | 開発環境（Ruby・PostgreSQL）を、PC に直接インストールせずにそろえられる |

- 今回チャレンジしたい点
  - 1つの回答から複数の診断軸に点数が入る配点と、軸ごとの偏りをならすスコア計算
  - 質問・配点・総合タイプを DB で管理し、あとから改善できる設計
  - テストと CI を使った、小さな単位での開発
- 不安な点
  - 本リリースでの他者診断（ログインなしの回答・URL の扱い）と AI 連携
  - 本番環境（Render）での運用
